# Choose the next useful method

Choose by the requested outcome and the uncertainty at the current phase. Keep
one lead and load only matching guidance. A route is not a checklist to run on
every task, and reading another skill's reference does not transfer ownership.
Resolve other skills by exact catalog name; never guess installation paths.

## Start with the project

Read the project's instructions, relevant skill metadata, run/test guides and
existing verification assets. Find project skills by covered behavior, surfaces
and source paths, including application control and formal checks. Prefer the
maintained project recipe when applicable; inspect its correspondence before
trusting it. If it is missing or stale, choose the smallest useful check or repair
within scope. Generate a reusable project skill when requested or when repeated
verification warrants one; do not turn a small edit into a new framework.

For a meaningful change, connect acceptance and preservation conditions to the
checks that can establish them. Use the existing task record when helpful. A
blocked check leaves a named limit, not permission to claim the dependent result.

## Route by phase and evidence need

| Situation | Guidance or support | Useful result before continuing |
| --- | --- | --- |
| Explain behavior, investigate a symptom, inspect history or a trace | Workflows [methods](methods.md); Measure for profiling or quantitative claims; Verify for a discriminating check | Source-backed explanation or bounded hypotheses; a confirmed mechanism where evidence permits. |
| Plan a feature or change an interface/state model | Workflows [methods](methods.md); Check for consequential assumptions; Arena for alternatives that need an actual comparison | Observable contract, state ownership, affected consumers and a way to settle the costly uncertainty. |
| Prototype a disputed approach | Workflows [methods](methods.md); Arena when independent alternatives are useful | An isolated runnable probe, observation and explicit limits; a supported decision. |
| Implement a new feature or extend existing behavior | Workflows [methods](methods.md); Verify's applicable testing, application or formal reference and relevant project procedures | Observable acceptance conditions met, existing behavior preserved and the integrated result checked. |
| Repair a reported defect or assess an existing fix | Workflows [methods](methods.md); Verify's `references/testing.md` and relevant project checks | Relevant failure evidence and a checked repair, or findings about the supplied artifact within review-only scope. |
| Refactor or migrate | Workflows [methods](methods.md); Verify's `references/testing.md` | Behavior pinned before movement; consumers, saved formats and external contracts accounted for; equivalent preserved behavior after integration. |
| Improve speed, cost or capacity | Measure and its `references/measurement.md` before/after changes; Workflows owns implementation | Valid comparable workload, correct output, bottleneck hypothesis and measured keep/revert decision. |
| Exercise a UI, CLI, service or library through its real interface | Verify's `references/application.md`; use the matching project control skill | Correct instance and usable readiness, real action and effects, retained evidence and owned cleanup. |
| Preserve a visual reference | Verify's `references/methods.md` visual checks plus application guidance | Comparison at matching states/viewports, including requested interactions and declared tolerances. |
| A consequential invariant needs more than sampled examples, or a model/proof already covers touched code | Verify's `references/formal.md`; `references/bend.md` only when relevant | Justified method and scope; source correspondence, executed obligations and meaningful fault sensitivity. |
| Assess correctness, design, readiness or evidence quality | Check and its `references/critical-review.md`; Verify/Measure for a specific unresolved probe | Actionable findings and remaining risks; independence and allowed writes remain explicit. |
| Open a PR, inspect its status, address findings, merge or release | Workflows [delivery](delivery.md); Check/Verify as needed | The requested endpoint on the actual current revision, with supported evidence and remote readback. |
| Delegate, pause, resume or clean up owned work | Workflows [coordination](coordination.md) | Actual inputs, ownership and evidence freshness; stopped writers and preserved work before replacement/cleanup. |
| Repeated failure exposes a reusable lesson | Workflows [notes](notes.md) | A scoped structural prevention or concise rationale, exercised against the failure and a valid case. |
| Evaluate or revise the skill pack | Configure only on direct request; its evaluation and routing references | An isolated candidate, meaningful fresh trials and requested delivery; installation is a separate endpoint. |
| Coordinate a bounded program or issue queue | Campaign only on direct request; its state/control reference | Checkable units, dependencies, budgets and evidence; no implicit schedule or message permission. |

## Hand off the right context

Give a specialist the question, requirements, concrete source and environment,
allowed writes, relevant project-skill/reference pointers and stopping condition.
Keep fixed evidence, prototype conclusions and evaluator answers out of briefs
when independence requires it. Workers return observations and limits; the lead
integrates changes and verifies the combined result. Missing delegation does not
excuse skipping applicable guidance or inventing an independent review.
