# Independent comparison details

Read before candidate delegation or judging.

Give every candidate the user goal, preserved contracts, common source/content
identity, environment, owned output, permitted writes, expected evidence and
stopping bound. Include necessary requirements; keep preferred conclusions and
other candidates' reasoning out. For designs, require realistic caller usage,
state ownership, success/failure/recovery flows, compatibility and a falsifiable
load-bearing assumption. For implementations, require relevant behavior evidence.

Use separate workspaces/task branches and mutable databases, ports, profiles and
outputs. For file-only shared-folder assignments, give disjoint files to workers
and reserve all Git operations for the coordinator. For cross-host transfer or
replacement, read the shared contract's coordination.md. Stop the old writer
before replacing it; timeout alone is not confirmation. Preserve incomplete output.

Prefer available model diversity without inventing identities. Same-model fresh
contexts can produce independent alternatives; report the actual limitation.
Sequential independent contexts are valid when concurrency is constrained.
Author-generated variants or self-judgment are useful fallback work, not independent
candidates or judging. Explicit stricter diversity requirements remain binding.

Separate hard gates from comparative qualities. Useful design criteria include
user value, ownership, consumer-facing simplicity, failure/recovery, compatibility,
verifiability and maintenance. A short implementation is not inherently better.
The judge receives frozen artifacts and the full rubric, with author/model labels
and the lead's preferred conclusion withheld on its first pass. Require evidence,
remaining risks and a recommended base, rather than scores alone.

One failed seat may be replaced after confirmed stop. If all candidates fail,
identify the common cause before one targeted reframe. These defaults do not cap
explicitly requested depth. Further rounds need an unresolved consequential
question and remaining authority/resources. Do not silently drop failed candidates.

Integrate through one owner. Explain how each graft fits the selected invariants;
reject conflicting state models or error policies. Refresh affected verification
on the exact synthesis. Keep useful losing ideas and failure evidence until the
owner has inspected and preserved them. Return open product choices with concrete
options and a recommendation; the agent owns technical integration decisions.
