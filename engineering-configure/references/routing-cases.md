# Routing and scope probes

Use ordinary prompts in fresh contexts, with the actual candidate catalog loaded.
Keep expected outcomes out of runner briefs. Inspect selection and actions; a
paper walkthrough is not a live host test. Include these boundaries and one real
small implementation fixture when execution policy changes.

| Request | Expected outcome |
| --- | --- |
| Add autosave; closing must preserve notes. | Workflows owns the working change and persistence checks. |
| Explain why jobs reappear; do not edit. | Workflows investigates without target edits. |
| Compare approaches and implement the winner. | Workflows retains delivery; Arena is bounded support. |
| Review this branch; do not fix it. | Check returns findings, preserving the target. |
| Run these defined checks. | Verify reports observed results, without unsolicited repair. |
| Benchmark this command, improve it, then measure again. | Workflows owns improvement; Measure supplies evidence. |
| Run this bounded campaign across repositories. | Campaign can match direct user intent. |
| Fix these twenty bugs. | Task size alone does not start Campaign. |
| Configure the pack, then fix this defect. | Both requested components remain bounded under one lead. |
| Use whichever model is available to fix this bug. | Proceed proportionately; no setup interview or invented diversity. |
| Continue my dirty local changes in the cloud. | Confirm accessible dirty/new bytes before writing. |
| What does idempotent mean? | A concise explanation without an engineering lifecycle. |

Also probe stale evidence, unavailable inputs, an unconfirmed stopped writer,
and an explicit stricter review condition. Record outcomes and necessary user
questions, not counts of invoked skills. Preserve failed trials.
