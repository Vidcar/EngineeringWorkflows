# Evaluate and save the actual change

Read for requested skill/procedure evaluation or promotion. Follow the host's
official skill-authoring process for editable locations and persistent changes.
An evaluation request alone does not authorize replacing the active skill.

Freeze baseline and candidate bytes, including dependent references and metadata.
Define the decision, hard constraints and useful outcome criteria before trials.
Choose a small representative task set with real artifacts and a plausible failure
case. Syntax, model agreement and prose claiming execution do not prove behavior.
For substantive changes, use fresh task-shaped runs or isolated fixtures, then
inspect actual artifacts, traces, checks and effects. Include ownership/routing,
read-only scope, recovery and honest completion where affected.

Keep conditions comparable and outputs isolated. Give runners ordinary requests
and necessary context without expected answers, preferred variants or earlier
reviewer conclusions. Preserve failed/partial trials. Distinguish observed action
from a proposed plan. Use bounded Arena for independent alternatives, Measure for
quantitative evaluation, Check for judgment or Verify for defined evidence needs.
Retain the current owner and assigned review depth; support does not restart work.

Inspect the exact combined pack after revisions, including references, metadata,
activation policy and representative behavior. Campaign and Configure require
direct user intent; never introduce them as automatic setup/support dependencies. Reproduce material findings and
refresh affected checks/review. For pack changes, use the resolved Workflows
`validate_pack.py --root INSTALLED_ROOT` and relevant bundled tests
in its scripts directory; these establish structure, not selection behavior. Use
[routing cases](routing-cases.md) when selection or scope changes. Stop when the inspected scope is supported, not
when every reviewer praises it. Any additional round needs unresolved evidence
or a named risk; explicit user-requested depth remains binding.

When promotion is authorized, validate, save and read back the exact personal-skill
artifact through the official process. Preserve rollback where supported. Report
evaluated versus saved versus observed behavior separately. If saving fails, retain
the candidate and identify the smallest supported resolving action; never claim
installation from a local draft or inferred UI state.
